## 一、整理本清单 `collated_edition/index.json`

### F-CE-01　六个必现字段

**适用**：`collated_edition/index.json`。
**要求**：**新入库必须**含 `work_id`／`total_entries`／`juan_files`／`text_quality`／`revision`／`revised_at` 六字段。
**理由**：现状 65/65 部全部具备，是唯一已经自然收敛到 100% 的字段集合，直接固化为硬约束成本为零。
**现状**：65/65 合规，0 处不合规。
**怎么修**：无需修，仅收口为规则防止今后遗漏。

### F-CE-02　`type` 非空

**适用**：`collated_edition/index.json.type`。
**要求**：**新入库必须**非 `null`。
**理由**：`type` 是唯一决定 `juan/*.json` 结构（是否有 `part/bian/lei`／`lue` 等扩展字段）的字段，
为 `null` 时下游无法判断按哪套字段读。
**现状**：64/65 合规，1 处 `null`——**已查明**：`Work/2/9/s/d59f2ofyy29s`
《補南北史藝文志》（96 卷，收在《二十五史藝文經籍志考補萃編》）。**建议值：`catalog`**——
依据两点：① 同丛编、同体例的《補後漢書藝文志》（`d59f2o2lm0ht`）现状 type 正是 `catalog`；
② 该部 `juan/001.json` 的 section 形态是 `{level, title, type: "category"}`
（如「小學類」），与 `catalog` 型作品的典型分类目录结构一致，不含 `kaozhen` 型
（如《隋書經籍志考證》`d59f2mp0flz6`）特有的 `part`／`bian`／`lei`／`chapter` 等扩展字段。
**本道只读，不改数据**——回填由文本总管指派的下一道执行。
**怎么修**：要人回填（本条已给出建议值与依据，不必再重新调查）。

### F-CE-03　`type` 枚举表（已裁：新入库只许 5 个正式值）

**裁决**（文本总管 2026-09-26 09:1x，回 `ask` §五·B）：**新入库必须**取
`{catalog, anthology, collated_edition, kaozhen, fragment_collection}` 五值之一；
`placeholder` **只作存量占位态**（须同时满足 F-CE-04b：`text_quality.grade` 也是
`placeholder`），**新入库不许再用**；`null` 新入库禁止（见 F-CE-02）。
**现状**：7 种取值中，5 个正式值合计 63/65；`placeholder` 1/65（现状与
`grade=placeholder` 已一致，0 处不合规，见 F-CE-04b）；`null` 1/65（见 F-CE-02，
已给建议值，回填后即合规）。
**怎么修**：`null` 那 1 处要人回填（同 F-CE-02）；`placeholder` 那 1 处**不算不合规**
（存量占位态本来就允许），发布前如需转正式值另计。

### F-CE-04　`text_quality` 统一 dict 形态

**适用**：`collated_edition/index.json.text_quality`。
**要求**：**新入库必须**是 dict，至少含 `grade`；`grade` 取值限定在现状枚举
`{rough, fine, ocr, source, placeholder, none}` 之内，新增取值先补本规范。
**理由**：现状 65/65 已是 dict 形态，`grade` 是唯一在其余全部三种资产
（`fragments`／未来 `full_text`）里都出现的质量分级字段，值得跨资产统一枚举。
**现状**：65/65 合规。**任务书交底「曾有旧式字段」核实为历史遗留，
现无 scalar／缺失，具体清理 commit 未查，如实存疑**。
**怎么修**：无需修。

### F-CE-04b　`type=placeholder` 必须配 `grade=placeholder`

**适用**：`collated_edition/index.json` 的 `type` 与 `text_quality.grade` 联动。
**要求**：**新入库必须**——若 `type` 为 `placeholder`（占位态），则 `text_quality.grade`
也必须是 `placeholder`，两者同步，不许一边占位一边不占位。
**理由**：F-CE-03 裁决把 `placeholder` 限定为「存量占位态」，占位态的判断依据
应该由两个字段共同确认，避免出现「type 说是占位、质量却标了 rough／fine」这类自相矛盾。
**现状**：1/65 部为 `type=placeholder`，其 `grade` 已是 `placeholder`，0 处不合规。
**怎么修**：无需修。

## 二、整理本纯文本 `collated_edition/text/*.md`

### F-MD-01　夹注记法：新入库用 spec 正规 `<…>`

**适用**：`text/*.md` 里的夹注（双行小字注）。
**要求**：**新入库必须**用 `guji-markdown` spec `<…>`（`spec/syntax.md` §1）。
**理由**：这是三方（用户 2026-09-10 裁「以 guji-markdown 仓库为主」＋ spec 本身 ＋
已有 4 部先行 migrate）都指向的唯一正规记法。
**现状**：`<…>` spec 生效 655 处／43 档／4 部（`d59f2o2lm0ht`、`d59f2nfhf8cg`、
`d59f2nl40936`、`d59f23o7ygw2`）已合规；**存量允许**旧形态 `⟨…⟩`（9,392 处，
仅千頃堂書目 `d59f2mel8d1c` 一部）继续存在，**不要求批量转换**。
**转换前置已满足**（文本总管 2026-09-26 09:1x 裁：`book-index-ui` 0.9.3 已于 09-26 上线，
新旧两种记法兼容渲染，目錄／原文两视图均已验）——08 档 §六·2「与 `book-index-ui`
同一上线窗口」的前提不再是拦路的，**转换按逐本自然转执行**（09-14 精神：不批量、
不为了转换而单开一道，随该部整理本下次改版顺手转）。
**怎么修**：机械可修（已有 `转记法.mjs` 三道闸验证过）；owner 与时机按「逐本自然转」，
不再需要单独等一个「下一波」窗口。

### F-MD-01b　`（（…））`（全角双圆括号）——宋史藝文志一部的已知例外

**裁决**（文本总管 2026-09-26 09:1x，回 `ask` §五·C「选 3」）：
**不为此扩展 `guji-markdown` spec**（该记号与 spec §2 半角 `((…))`「补字」语义
同形不同义，容易和正规补字记号混淆，只为一部书的历史遗留形态扩展 spec 不值得）；
**记为存量已知例外**，与 F-MD-01 的 `⟨…⟩` 一样按「逐本自然转」处理，
**不批量转换、不单开道**。
**现状**：913 处／43 档，仅宋史藝文志 `d59f2gdp696q` 一部，无变化。
**怎么修**：随该部下次整理改版顺手转为 `<…>`，不强制现在做。

### F-MD-02　`〔…〕` 只作校勘记引出，不作夹注

**适用**：`text/*.md` 里的 `〔…〕`。
**要求**：**新入库必须**只把 `〔…〕` 用于校勘记／考证按语／著录出处一类内容
（与 `guji-markdown` spec §12 保留语义「校勘记引出」相合）；**不得**用作注家夹注
（该用 F-MD-01 的 `<…>`）。
**理由**：spec 明令 `〔…〕` 为保留记号，「实现不得赋予其他语义」；
现状本仓 `〔…〕` 已压倒性是校勘记用法（08 档实测：`book-text` 内注家夹注 0 处，
汉志分层本那份非 `book-text` 的另一份文件才有注家夹注用法，且不在本仓写域内）。
**现状**：11,894 处／502 档，未逐处复核是否 100% 属校勘记（08 档旧数是 74.3%
校勘记＋两可 13.3%，且已裁「两可留着不动」）。**存量允许**保持现状，两可部分
不因本规范重新审查（既有裁决已定）。
**怎么修**：不需要，只是新入库时的边界提醒。
**裁决**（文本总管 2026-09-26 09:1x，回 `ask` §五·D）：**不另开道做语义抽查**，
维持「两可留着不动」既有裁决，本条到此为止。

### F-MD-07　同一部书内标题层级不跳级

**裁决**（文本总管 2026-09-26 09:1x，回 `ask` §五·F①）：**新入库必须**——
同一份 `text/*.md` 内，标题层级（`#` 个数）**不许跳级**（如 `#` 之后直接出现 `###`，
中间未出现过 `##`）。**不写死全局映射**（各体裁标题层级对应的语义不同，
一刀切会错——统一映射表留给 M3 展示格式研究一起定）。
**理由**：跳级是纯结构性缺陷，与「这级具体代表什么」无关，机械可查、误伤面极小。
**现状**：48 处跳级／40 档／1,736 档（2.3%）。
**怎么修**：机械定位（脚本报出具体行号与层级），**改法要人看**——补回缺失的中间层级
标题还是把该标题降级，取决于原书实际结构，不能机械脑补。

### F-MD-08　同一部书内标题层级语义一致性（报告用，不判定）

**裁决**（文本总管 2026-09-26 09:1x，回 `ask` §五·F②）：**只报数，不判定**——
校验器报出每部书用了哪几级标题（如「这部书只用了 `#`／`##`」），**是否每级语义前后一致
要人看**，不机械判断对错。
**理由**：「同一级标题语义是否一致」需要理解内容才能判断，机械只能报「用了哪几级」
这个事实，不能替代人的判断。
**现状**：全仓 `#`(1,669 行)／`##`(10,199 行)／`###`(18,899 行)／`####`(446 行)四级并存，
按部拆分的分布未逐部统计（属校验器逐部运行时才有意义的数，不在全仓画像范围）。

### F-MD-03　同行括号必须闭合

**适用**：`〔…〕`、`⟨…⟩`、`<…>`、`（（…））` 四种括注/夹注记号。
**要求**：**新入库必须**同行闭合（spec §0.2「行内记号不跨行」，闭合数为 0 差）。
**理由**：跨行/未闭合会被 spec 判定为「未闭合即字面」（§0.3），静默变成正文，
且已实测存量里的未闭合无一例外是 OCR 讹字（该开括号打成别的字符），不是真实的
「记号本来就该跨行」，说明这条约束不会误伤任何真实用法。
**现状**：`〔…〕` 同行未闭合 **17 处／4 档**（不合规，机械可查，OCR 讹字导致），
`⟨…⟩`／`<…>`（spec 生效口径）未闭合 0 处。
**怎么修**：机械可修（定位到具体行后人工核对原文补回缺失括号，因为需要看影印本判断
该是哪个字，属于「要人看」的机械可修——脚本能报出位置，改字要人核）。

### F-MD-04　页码注释：新入库鼓励使用，不作硬约束

**适用**：`text/*.md` 页码标记。
**要求**：**新入库鼓励**用 `<!-- pN -->`（04 档定案 3，已定），**不列为「必须」**——
理由见现状：使用率过低，列为「必须」会让第 3 步校验器在 99.6% 的档上报「不合规」，
噪音大于信号，且 04 档定案本身针对的是「忠实底本 md」这一特定体裁（见 F-MD-06），
并非全部 65 部整理本都适用。
**现状**：7/1,736 档使用。
**怎么修**：不需要，鼓励项不进校验器 `--strict` 失败条件。

### F-MD-05　整理者的话一律注释

**适用**：`text/*.md` 里的书志头、校勘按语、出版说明、整理后记。
**要求**：**新入库必须**将这类「整理者说的话」写成 `<!-- … -->` HTML 注释，
不进正文层（04 档定案 4 ＋ 裁二，已定，本档照抄）。
**理由**：与 F-MD-05 判准一致——「原书作者与注家的话」才进正文，整理者的话一律注释，
避免污染第二层解析。
**现状**：68/1,736 档已有此类 HTML 注释（未逐处核实内容是否 100% 符合「整理者的话」
这一判准，本次画像只统计有无，未做语义抽查）。**存量允许**未采用注释形式的旧档继续。
**怎么修**：不需要，新入库时人工判断「这话是谁说的」（04 档已给判准）。

### F-MD-06　一条一行——仅限「忠实底本层」体裁

**适用**：以「忠实底本 md」为体裁的整理本（04 档定案 2 的适用范围）。
**要求**：**新入库若采用忠实底本体裁，必须**一条一行。
**理由**：04 档定案，且明确这是「第一层」体裁专属规则——`verify_md.py` 已经区分
`line` 模式（忠实底本）与 `heading` 模式（結構化产物，如補南齊書經籍志），
说明本仓客观上已有两种并存的体裁，不能把「一条一行」当成对全部 65 部整理本的通则。
**现状**：本次画像未按体裁分类逐部核实（标题层级统计是全仓混合口径，
体裁与标题层级的映射留给 M3，见 F-MD-08）。
**怎么修**：不适用（规则本身只约束「选了这个体裁」的新入库，不约束既有体裁选择）。

**适用**：`fragments/*.json`。

## 五、抓取素材 `sources/`

### F-SRC-01　目录形态：不强约束

**适用**：`Work/<wid>/sources/<来源>/`。
**要求**：**不定强规则**。仅要求 `<来源>` 目录名为来源标识（如 `ctext`／`source_text`），
不得与 `collated_edition`／`fragments`／`full_text` 等既定目录名冲突。
**理由**：样本量极小（2/1,248 部有此资产，2 种形态），不宜从 2 个样本归纳强约束，
归纳出来的规则大概率在下一个来源出现时就要改。
**现状**：2/2 部符合（目录名分别为 `ctext`、`source_text`，均不与既定名冲突）。
