# decision.json 规范草案（候选字层）

> 状态：**草案**，2026-10-06 文本总管应网站 #444 之请起草，待用户拍板后再进 guji-format（`spec/07-guji-decision.md`＋schema）。
> 适用：book-text `original` 每章一份 `NNN.decision.json`，存 main，不进文本版本号。

## 一、定位
- char 只记定下来的那一个字；**拿不准的格，其他候选字放这里**，按格位 key 挂在 char 上。稀疏：只有存在候选的格才有条目。
- 展示用：网站在对读正文里标出这些格，点开看候选与依据。
- 不改文本。裁定后要改字，改 char（文本线 patch）；decision 里把该条状态改为已裁。

## 二、文件结构
```jsonc
{
  "schema": "guji-decision/0.1",
  "book_id": "96mid1ogzk",
  "volume": 3,
  "items": [
    {
      "a": "3:4:12",            // 格位 key，必须在同章 char 存在
      "c": "撰",                 // 校验字：等于 char 该格当前的字
      "kind": "存疑",            // 存疑／异体
      "status": "待裁",          // 待裁／已裁／驳回
      "cands": [                 // 其他候选，按可信度从高到低，≤5 个
        {"t": "𢰅", "src": "cv",  "conf": 0.41, "why": "字形匹配次优"},
        {"t": "譔", "src": "gemini", "note": "对读他本作譔"}
      ],
      "by": "human",             // 已裁时：谁裁的（human／rule）
      "note": "可选，一句话依据"
    }
  ]
}
```
| 字段 | 必填 | 说明 |
|---|---|---|
| `a` `c` | 是 | 同 norm：格位 key＋校验字，改文本后对不上的条目要修 |
| `kind` | 是 | `存疑`＝不确定这格是什么字（识别／漫漶／形近）；`异体`＝字是对的，不确定该不该并到通行字、候选是可能的通行字 |
| `status` | 是 | `待裁`＝还没人定；`已裁`＝人已定（定下的字已在 char，`c` 即结果）；`驳回`＝候选都不成立 |
| `cands[].t` | 是 | 候选字 |
| `cands[].src` | 是 | 来源：`cv`／`ocr`／模型名／`human` |
| `cands[].conf` | 否 | 0–1，来源自报的置信度，仅供排序 |
| `cands[].why` `note` | 否 | 依据，一句话 |

## 三、回答 #444 的两个问题
1. **候选只展示还是也参与检索？** 先只展示。检索只用 char（定下的字），否则一个字多个写法会让命中数和高亮对不上。以后要「搜候选」，由网站加开关，不改本格式。
2. **异体／存疑／待裁要不要分开标？** 要分，但是两个维度：`kind`（存疑／异体）说疑什么，`status`（待裁／已裁／驳回）说到哪一步。网站建议：待裁的存疑最醒目；已裁、驳回默认不标（或灰标）；异体与 norm 对应——norm 记已定的异体映射，decision 的「异体」记还没定的。

## 四、与其他文件
- **版本**：decision 不跟踪版本号；`index.json` 用 `decision_file` 声明，缺则无候选。裁定改了 char，才算文本线 patch。
- **谁写**：候选由 CV 导出器、Gemini／GLM 等候选文件产出，**入库与改 status 只由 Claude 道／本地整理会话做**（外部模型只出候选文件，见外部模型分工）。
- **校验**：`a` 在 char 存在、`c` 等于 char 该格字、同一 `a` 只一条、`cands` 非空（驳回也留着原候选）、`已裁` 的 `c` 不得出现在 `cands` 里。我补进 `validate_text_format.py`（规则 F-OV-04）。
- **体量**：稀疏，预期每册几百到几千条；vol03 暂无数据，网站先按样例开发。
