## 一、仓库流程（已定）

1. **main 受保护**：一律走 PR。一批活开一个分支（`<道名>-<主题>`，比如 `t65-wiki-match`），分支上可以多次提交。整批做完开**一个** PR，审过 **squash merge**。`wip/` 前缀是反复改动中的工作分支（比如 `wip/siku-vol02`），用户点头前不并 main。
2. **谁来合**：
   - 日常批次由文本总管审过就合，包括入库、修正、撤除 50 部以内。
   - 下面这些等用户点头：撤除超过 50 部；改全仓结构或规范；`original` 任何一条线升 **major**。
3. **开 PR 前**：先把 main 合进分支，用 `build_texts_index.py --root` 重建 `index/texts`，再跑完下面两项，结果贴进 PR 描述：
   - `validate_text_format --strict --baseline` 退出码为 0；
   - `validate-collated --root` 通过。
4. 不做 CI 必过检查，靠审 PR 把关。

## 二、版本跟踪的范围

| 内容 | 跟不跟踪版本 | 说明 |
|---|---|---|
| **`original`**：本项目自己从书影做出来的文本，比如四庫總目 `Book/.../96mid1ogzk/original/` | **跟踪，分三条线** | 本文的对象 |
| 维基文库、Kanripo、识典的转录（`default`、`kanripo/`、`wikisource-2/` 等） | **不跟踪** | 文本是上游的，我们只搬运和清洗。来源修订号（revid、dump 日期）照记在 `source` 里，就够追溯了。现有 index.json 里的 `revision: "1.0.0"` 留着不管，以后不再维护 |
| 整理本（`kind=collated`） | 不在本方案内 | 沿用 book-index 的整理本版本规定（`2026-05-版本控制与不可变性.md` §4）以及 `bump-collated.py` |

## 三、三条线各管什么

`original` 的数据分三层，三条线各自有 `MAJOR.MINOR.PATCH`，互不牵连：

| 线 | 文件 | 跟踪的是什么 | 不管什么 |
|---|---|---|---|
| **文本** | `NNN.char.json`（10-06 前是 `NNN.lines.md`） | 每一格定下的字：分列、夹注、抬头、阙文（guji-format 02 char） | 像素框（`cord.json`）、候选字（`decision.json`） |
| **标点** | `NNN.punct.json` | 句读、点号、书名号、引号、分段 | 字本身 |
| **实体** | `NNN.entity.json` | 专名的区间、类型（人、地、书、官、朝代），以及链到 book-index 的 id | 字、标点 |

### 版本号记在哪里（每册一套）
- **标点、实体**：各自的 json 顶层写 `"version": "1.2.0"`，再写 `"text_version": "1.4.1"`，说明是对着文本的哪一版做的。
- **文本**：版本记在 `original/index.json` 的每章条目里（`lines.md` 是纯字流，不放元数据），比如 `{"n": 2, "file": "002", "text_version": "1.4.1", "punct_version": "1.2.0", "entity_version": "1.0.3"}`。三条线的版本在这里一眼可见，网站也从这里读。
- **每次升版本**，在 `original/CHANGES.md` 记一行：日期、册、线、新版本号、一句话、PR 号。

### 三条线之间的关系
- 标点、实体靠坐标锚在文本上，每个锚点都带校验字。
- 文本改了以后，校验器逐个检查标点和实体的锚点字是否还对得上：
  - 对得上：伴生层不用动，只把 `text_version` 更新过去，这不算伴生层的改动，不升它的版本；
  - 对不上：伴生层按对不上的规模修，修好以后它自己升 patch 或 minor（见下）。
- **伴生层的等级不得高于文本**：标点、实体的 major 不能大于文本线的 major。文本还没到出版级，伴生层也不能先升（10-05 用户定，校验器 F-OV-01 查）。
- **每册只有一份标点稿、一份实体稿**入库，就是 `NNN.punct.json`、`NNN.entity.json`。几个模型的对照稿只在本地测试，不进仓（10-05 用户定）。
- **书名两层都记**：大模型识别出的书名，在标点层出一对 `《》`，同时在实体层出一个 `work` 实体，挂 book-index 的 id。两层的起止要一致（10-05 用户定）。
- 网站可以显示三条线各自的版本，比如「文本 1.4.1 · 标点 1.2.0 · 实体 1.0.3」。

## 四、三级的总原则（用户定）

- **major = 质量等级。** 从严规定，轻易不升，绝大多数时候停在 1。
  - 1 是可用；
  - 2 是**出版级**；
  - 3 是**定本**：几乎完全确定、不会再改。

  升 major 要有成文的验收记录（抽检数据和签核人），并且用户点头。major 一升，minor、patch 归零。
- **minor = 比较大的改动**：新功能、新的分段、整批字符转换、质量有小幅提升、整册重跑。
- **patch = 其余所有小范围改动。** 这是最常见的。
- 不确定 patch 还是 minor，选 minor；major 不存在「不确定」，达不到门槛就不升。

## 五、各线的等级门槛（major）★

### 文本线
| 等级 | 门槛 |
|---|---|
| **1 可用** | 每一格都有定字；疑难、阙文、残字按规范记下（`□`、`[[]]`、guess）。机器定字加上自动放行闸。人审没有覆盖全册也可以 |
| **2 出版级** | 全册人工逐字校过一遍，疑难字都有裁决记录。**随机抽 ≥2,000 字，错字 ≤2**（约万分之一）。阙文、异体、组字的写法全部合规 |
| **3 定本** | 两遍独立校对，并且至少和一种别的版本或权威整理本对勘过，每处异文有校记或裁决依据。**随机抽 ≥10,000 字，错字 ≤1**。用户（或指定专家）签核 |

### 标点线
| 等级 | 门槛 |
|---|---|
| **1 可用** | 机器标点（LLM），只插标点、不改字。**抽 200 处，一致率 ≥95%** |
| **2 出版级** | 全册人工审读过一遍，书名号、引号层级、分段符合标点规范。**抽 500 处，一致率 ≥99.5%** |
| **3 定本** | 对照至少一种权威点校本逐段核过，分歧处有记录和取舍理由。**抽 1,000 处，一致率 ≥99.9%**，用户签核 |

### 实体线
| 等级 | 门槛 |
|---|---|
| **1 可用** | 机器识别加自动链接。**抽 50 个，类型和边界的精确率 ≥90%**；挂错 book-index 条目的比例另报，≤5% |
| **2 出版级** | 所有实体人工确认过类型、边界、链接。**精确率 ≥99%**。逐段抽 20 段查漏，**召回 ≥95%**。没有「存疑」链接 |
| **3 定本** | 全册逐段人工补过漏，**召回 ≥99%**。所有链接对象在 book-index 都已正式建档，且不是「存疑」状态。用户签核 |

## 六、minor 和 patch 怎么分（各线举例）

| 线 | minor（较大改动） | patch（小范围） |
|---|---|---|
| **文本** | 整批字符转换，比如 PUA 转 Unicode、组字式转 IDS、某个异体整册统一记法；新的分列或夹注规则整册重排；一批人审裁决落地，使人审覆盖率提高 ≥10 个百分点；新增一种标记功能，比如 `zi` 层、抬头记法 | 改正个别字（一次 PR 在一册里不超过约 50 处，且都在已知位置）；补几处阙文的 guess；记法笔误 |
| **标点** | 整册重跑或换模型、换提示词；新的分段规则；新增标点类型，比如引号分层；批量修正一类错误，比如「曰」后统一加冒号 | 改几处、几十处标点；修锚点没对上的少量条目 |
| **实体** | 新增实体类型；整册重识别；一批 new_candidate 建档后集中回填 book-index id（A6）；匹配器换了规则后重新链接 | 改个别实体的边界、类型、链接；修少量锚点 |

**「小范围」怎么数**：以一次 PR 为单位，一册里改动的位置不超过约 50 处，就算 patch；超过，或者是按规则成批改的，就算 minor。★

## 七、什么时候开始编号
- `wip/` 分支上反复改的时候**不编号**，版本号字段可以先写 `0.x`，也可以不写。
- **第一次并进 main 时定为 `1.0.0`**，前提是够得上第 1 级门槛；够不上就不并 main。
- 之后每次 squash merge，凡是动到的线，按本方案升级，在 PR 描述里列一张「册 · 线 · 旧版本 → 新版本 · 理由」表，文本总管审的时候对着 diff 核。

## 九、落地实现（T67 #400，10-05）

- **升级脚本** `scripts/book-text/bump_original.py <original 目录或条目目录> --line text|punct|entity --level patch|minor --note "…" [--pr N] [--chapter NNN]`；首次并 main 用 `--init`（三线都定为 `1.0.0`，已 ≥1 的拒绝）；`--level major` 直接报错。
  - 升文本线后自动核标点、实体两层的锚点：全对得上就只把它们的 `text_version` 跟过去；对不上就不动并列出来，修好后再对那条线跑一次脚本。伴生层锚点没修好时，脚本拒绝升它。
  - 中途报错一个文件都不改；`CHANGES.md` 不存在时自动建表头。
- **校验器** `validate_text_format.py` 新增三条 HARD 规则（10-05 F-OV-01 补「伴生层 major 不高于文本」），只扫 manifest 里 key=`original` 的版本：
  - **F-OV-01** 三线版本号是 `MAJOR.MINOR.PATCH`，≥1.0.0 且 major ≤3（与 guji-format 04/05 schema 同口径）；`index.json` 的 `punct_version`／`entity_version` 与伴生 json 的 `version` 一致；伴生层 `text_version` 不超前于文本。
  - **F-OV-02** 伴生层 `text_version` 落后于文本时，逐个核锚点校验字（标点 `anchor`＋`pre_char`；实体 `anchor.start..end`＋`text`），对不上就报。
  - **F-OV-03** 任一线 major ≥2 必须带验收记录：文本线在 `index.json` 该章的 `text_review`（T68 起改为 `char.json` 顶层的 `review`），标点、实体在各自 json 顶层的 `review`；至少含 `date`、`signed_by`、`sample`（抽检数据）。
  - `original/` 下的 `NNN.lines.md／punct.json／entity.json／rich.md／pages.json` 和 `CHANGES.md` 不再被 F-FT-01 当成「章节文件名不符」。
- 坐标口径与 open-guji-cv `render/siku_extract.parse_lines_md` 一致（空行不占列；双行夹注 `<甲|乙>` 甲是右列、先读，子列 a，乙是左列，子列 b，与 guji-format 02/04 同口径），实现在 `项目进展/古籍文本/scripts/original_version.py`，两边共用。
- 自测：`python3 -m unittest tests.test_bump_original`（在 `scripts/book-text/` 下跑），覆盖 init、patch、minor、major 拒绝、锚点漂移报错、≥2 级缺验收记录。
- 注意：cv 现有流水线写的 `"version": "0.1.0"` 原本是格式版本（格式另有 `$schema` URL 可认），按本规范改作**内容版本**；T66 #397 改流水线时补 `text_version`。

## 十、改读 char（T68 #417，10-06）

文件体系见 book-text `docs/ORIGINAL.md`。本节是 overview 这边的脚本和生成分支怎么用。

### 脚本（都在 `scripts/book-text/`）
| 脚本 | 做什么 |
|---|---|
| `original_char.py` | 库：旧 lines.md → char 的 `pages`；char → lines.md；char＋punct＋entity → rich.md（口径照 cv `siku_extract.assemble_volume`，cv 冻结，重写不 import）；旧 pages.json → cord |
| `convert_original_char.py <original 目录> --schema-dir <guji-format>/schemas [--write [--migrate]]` | 旧形态 → char.json＋cord.json。每册核：char 生成的 lines.md 与原文件逐字节一致、格位与 `lines_slots` 一致、cord 按读序逐格字相同、过 schema；任一不过整批不写。`--migrate` 另把 index.json 改成 `*_file` 字段（并补 `text_version` 镜像），删掉 lines.md、pages.json、rich.md、NNN.md |
| `gen_original_derived.py <book-text 根｜条目｜original 目录> [--check]` | char → lines.md；char＋punct（＋entity）→ rich.md；index.json 加 `lines_file`、`rich_file`。标点层还是旧格式（条目没有 anchor）的册只出 lines。`--check` 只比对不写 |
| `publish_original_derived.sh <book-text 克隆> [源分支] [生成分支] [--no-push]` | 借临时 worktree：生成分支上接一个新提交，树 = 源分支的树 ＋ 生成物，提交说明写源提交号；推上去 |

- `original_version.py`（与校验器共用）：文本线读 `NNN.char.json` 顶层 `version`；锚点按 char 格位核（`char_slots`、`anchor_mismatches(char, …)`）；`dump_compact` 写 char／cord 一格一行（比 indent=2 小一半多）。
- `bump_original.py`：`--init` 把 char.json 和 index.json 镜像都定 1.0.0；`--line text` 升 char.json 的 `version`；major 的验收记录写在 char.json 顶层 `review`。
- 校验器：F-OV-01 查 char.json 的 `version` 和 index.json `text_version` 镜像一致；F-OV-03 文本线看 char.json 的 `review`；新增 **F-OV-04** 查章条目 `*_file`：`char_file` 必填，写了的必须存在且文件名是 `NNN.<代号>.json／.md`。
- 自测：`python3 -m unittest discover -s scripts/book-text/tests -p 'test_*original*'`（找得到 `../guji-format/schemas` 时顺带核 schema）。

### 生成分支 `derived`
- 名字定为 **`derived`**。每个提交 = 源分支某提交的整棵树 ＋ 各 `original/` 下的 `NNN.lines.md`、`NNN.rich.md`，index.json 加 `lines_file`、`rich_file`。只由脚本写，不手改，不往回并。
- **什么时候建**（10-06 #417 分工调整）：底本 char／cord 由整理总管出；等它落到 `wip/siku` 后再正式建 `derived`。（T68 10-06 先越权建过一次、并往 `wip/siku` 推过 `8c15b677a`，撤不撤待总管定，见 #417。）
- **四庫还在 `wip/siku` 时**：从 `wip/siku` 生成：
  ```bash
  bash <overview>/scripts/book-text/publish_original_derived.sh <book-text 克隆> wip/siku derived
  ```
  `wip/siku` 上 original 的 char／punct／entity 每推一次，就跑一次。
- **并 main 以后**：每次合入动到 `original/` 的 PR 后，由合 PR 的人（文本总管）跑：
  ```bash
  bash <overview>/scripts/book-text/publish_original_derived.sh <book-text 克隆> main derived
  ```
  第一次从 main 生成时，生成分支的树整体换成 main 的树（wip 上的工作文件随之消失），历史接在原 derived 后面。
- 前端读 lines／rich 时读 `derived` 分支；读真源读 main（ORIGINAL.md §二）。

### 转换时发现的（四庫 vol02、vol03）
- 旧 pages.json 里 cv 写的格位是**几何格号**（从最上一格起数），和 lines.md／char 的格号（挪抬 `.` 计格、抬头负格、无第 0 格）不全一致：vol02 有 1,213 格、vol03 有 4,000 格不同（页、列都一致，只差格号）。标点、实体的锚点用的是 lines.md 口径，所以 char 沿用 lines.md 口径，cord 的框按读序（两边字流逐字相同）挂到 char 的格位上。cv 解冻后直接出 char／cord 时（#398）要按 02 §二 的格号口径出。
- 两册第 1、2 页（封面、扉页）的 body 区域 `box` 为 null（没测出版框），schema 要求有框，cord 不收这两个区域。
- 每册最后一页 pages.json 有空列（没有字的列），char 只收有字的列，cord 照收全部列框。
- **cv 两个 `parse_lines_md` 对 `^.`／`^..` 列口径不一**：`render/siku_extract.py`（标点、实体锚点用）按挪抬算，首字 `dots+1`；`formats/guji_format.py::derive_anchors`（A1 导出 pages.json 用）按抬头算，首字 `-raised`。终稿三 vol02 有 8 列 140 格、vol03 有 84 列 1,565 格不同，其余逐格相同。**10-06 定为 cv 口径**（#419 CV 总管拍板）：`original_char.parse_lines_md(text, cord)` 的格位、空列取自 cord（`74ad53d`）；不给 cord 的旧 lines 口径只作兼容。
- vol03 的 `003.punct.json` 还是旧格式（条目没有 `anchor`，只有 `char_offset`），出不了 rich；等 T66 #397 按新口径重跑。
