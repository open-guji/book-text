## 一、评估

### 1. 覆盖：Kanripo 全部文本 × book-index Work

**数据来源**：`kanripo/KR-catalog`（GitHub 公开仓，org-mode 书目，含 KR 编号、题名、朝代、作者、四部分类），

### 2. 质量：10 部抽样比对

**方法**：从「确认」且「已有维基全文」的 741 部里，按經史子集道佛各挑 1～2 部（含短小说、笔记、诗集、类书等
不同体裁），取每部第一卷/篇，与 book-text 现有维基文库全文逐字对齐（`difflib`，去标点，异体字先按
`match_variants.json` 归一再判等价 vs 真差异）。**10 部样本一次到位，未追加轮次。**

**10 部 match/min 平均 95.68%**（92.4–99.98% 区间），与 Z8 对《全唐文》的结论（Kanripo 对影像 99.30%、
维基系 97.2%）方向一致：**Kanripo 与维基文库系（含四库/SBCK底本）在有效重合部分高度一致**，四部差异主要是：

1. **异体字统一**（KR 把「髙/㓗/爲/寳/栢/㫁」等统一录成「高/潔/為/寶/柏/斷」，各样本均占「差异」大头，
   属已知系统差，非转写质量问题，见任务书 §一.2 与 Z8 报告）；
2. **章节颗粒度不对齐是本轮新发现的坑**：Kanripo 按「卷」切文件、维基文库有时按「篇」切页面（論衡最典型），
   直接拿文件序号对齐（`_001.txt` ↔ `001.md`）**不可靠**，必须按 `index.json` 里的章节 `title` 字段
   （如「卷01」「序」）匹配后再比对——本道第一轮就在嶺外代答/鬼谷子上踩了这个坑（`001.md` 其实是「序」，
   真正卷一是 `002.md`），改按标题重新取值后才拿到上表数字。**这是给未来把 Kanripo 接进整理流程的人的直接提醒**；
3. **少数样本 Kanripo 底本比维基（多为 SKQS 系）更完整**：伯牙琴、詠物詩两部里维基对应处是抄本残损占位符
   （`<原缺N字>`/`□`），KR 对应处却是实字——说明 Kanripo 有的书用的底本比维基抄录的四库本更善，
   **值得作为校勘参照，不只是"次要备份"**；
4. **非 BMP 字/IDS 占位丢失**：本轮 10 部一手抽样恰好没撞到（全唐文试点里撞到了大量，见下方§二），
   但 Z8 报告已确认是 Kanripo 系统性问题，具体见下节格式。

原始比对脚本与逐条差异见 [quality_results.json](样本/T25/quality_results.json)（含每部匹配数、异体数、其余差异样例）。

### 3. 格式：Kanripo → 我们存储的映射方案（只出方案，不定案）

**Kanripo org-mode 源文件结构**（`kanripo/KR<code>/KR<code>_NNN.txt`，一卷一档）：

```
# -*- mode: mandoku-view; -*-
#+TITLE: <书名>
#+PROPERTY: ID KR<code>
#+PROPERTY: BASEEDITION <SBCK|NFKB|...>
#+PROPERTY: JUAN <卷次>
<pb:KR<code>_<版本>_NNN-Na>¶
<正文，一行=刻本一列，行内无标点>¶
...
```

- **`<pb:...>` 叶码**：本轮验证不止全唐文（NFKB 底本）用这个记法，SBCK 底本（春秋繁露等）也用同一 `<pb:...>`
  格式（只是编号规则里的版本段不同），**是 Kanripo 全库通用的折叶标记**，可放心当通用字段处理。
- **IDS／非 BMP 占位有两种不同写法**，需要分别处理，不能假设只有一种：
  - NFKB 底本（全唐文用的这版）：`[:#AS-8949:⿱廾...]` 方括号+部件拆字；
  - SBCK 底本（本轮质量抽样春秋繁露用的这版）：`&KR4229;`（未查到本轮质量样本的具体解出方式，只在原文里见到，
    未展开——本道未对质量抽样的 10 部做补字，仅在全唐文试点里处理过 NFKB 记法）。
  两种记法在**同一份机械转换脚本里都要识别**，不能只按全唐文那一种写死。

**两个映射方案**（**结构性决定，交用户/文本总管审**，本道不定案）：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 最低限度**（本轮全唐文试点采用） | 逐列拼接成连续段落，`<pb:...>` 丢弃或另出旁档（本道用「卷→CADAL件号」粗粒度旁档，非逐列精确映射） | 实现快、体积小、和现有 book-text 全文格式（如维基来源）一致，便于统一渲染 | 丢了「一行=一列」这个 Kanripo 独有的强信息，日后要拿它给 CV 当金标/参照就要重新对齐 |
| **B. 保留原书分行** | 每列单独一行落盘，配合 [自校文本格式草案](../../整体设计/2026-09-自校文本格式草案.md) 的 `line_is_column: true` 元数据，`<pb:...>` 转成精确到列的旁档表 | 保留最多信息，天然适合给 CV Step5-d 做整理本对齐参照 | 格式与现有 book-text 全文（维基来源）不兼容，需要新的渲染/展示支持，guji-workspace 那边已经在按这个思路存（见 Z8/Z9/Z12 的 corpus 文件） |

新书整理 Z8/Z9/Z12 三道在 guji-workspace 分支 `z8/qtw-draft` 已经按接近方案 B 的思路（column-per-line，
`line_is_column: true`）产出了《全唐文》卷1–30、307–310 的语料并逐步补字校核，本道试点复用了这份成果做机械转换
（见下方§二）。**如果最终决定书全库都走方案 B，那份 corpus 的经验（补字方法、硬切踩过的坑）可以直接复用。**

### 4. 许可与署名

- Kanripo 全库 **CC BY-SA 4.0**（其 catalog 仓 `KR-catalog` 与各文本仓 `KR<code>` 均未见例外声明），
  **可以进公开仓**，与任务书前提一致。
- **署名要求**（BY 条款）：至少需标注来源名称（"Kanseki Repository (Kanripo)"）、链接（`kanripo.org` 或对应
  GitHub 仓）、具体版本（commit hash）。本道产出的 `index.json` 已按此写好 `source` 字段（见§二）。
- **相同方式共享要求**（SA 条款）：凡衍生自 Kanripo 文本的转换结果，也须以 CC BY-SA 4.0（或兼容协议）授权，
  **不能整体标成 book-text 仓自己的 CC0**。book-text 仓根 `LICENSE` 是 CC0，但**已有先例**：现有 826 部
  维基文库来源的 `full_text/*/index.json` 里都单独标了 `"license": "CC BY-SA 4.0"`，说明这个「仓级 CC0 + 单条
  按来源如实标注」的模式项目里已经在用，**Kanripo 照此惯例办即可，不必另起新机制**。
- **网站展示缺口（不是 Kanripo 独有，属既有欠账）**：核过 book-text 仓根目录与 `README.md`，
  **没有找到任何仓级的 CC BY-SA 汇总署名/NOTICE 文件**；F2-关于与内测页任务书本身未提及具体许可文案
  （据排班记录该道后续按「许可逐仓如实写」处理，本道未核实网站上线后的实际呈现）。这意味着现有 826 部
  维基文库来源全文，网站上目前展示 CC BY-SA 署名的方式待核实是否到位——**这是加 Kanripo 之前就存在的缺口，
  建议网站总管一并核实，不要因为 Kanripo 才第一次触及这个问题**。
