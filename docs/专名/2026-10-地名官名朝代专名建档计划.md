## 三、各类建档方案

### 1. 朝代（最先做，闭集，约 50–80 条）
- 一份人工可审的闭集表：先秦、秦、西汉、东汉（附「漢」「前漢」「後漢」别名）、三国各国、西晋、东晋、十六国、南朝宋齐梁陈、北朝魏齐周、隋、唐、五代各朝、北宋、南宋（别名「宋」「南北宋」按语境）、辽、金、元、明、清……
- 字段：`primary_name`、`alt_names`（著录形）、`start_year`、`end_year`、`cbdb_dy_code`（运行时读库，不抄表；该方案 §2.1d 已发现手抄表有错）、`parent`（如 南朝宋 → 宋 的歧义要显式处理）。
- 帝号／年号**不**算朝代：徽宗→人物（宋徽宗），萬歴→年号（见下「4. 年号」）。
- 与人物的 `dynasty` 字段打通：之后人物条目的朝代改为引用朝代条目 id，而不是自由文本。

### 2. 官名（官职）
- 与 `collective`（官署）分开：新增 subtype `office`，`place` 同理需目录总管确认。
- 数据源：CBDB `OFFICE_CODES`（官职码表，含各朝官职与品阶）为骨架；《历代职官表》等可后补。
- 复合官名处理：「地名＋官职」「殿阁＋官职」在 entity.json 里**保持整段一个 span**（读者看到的就是原文那几个字），但在 target 里拆出 `base_office`（官职本体，如 教授、大學士）＋ `qualifier`（韶州、資政殿），本体匹配 CBDB／官职表，限定语另挂地名／机构。
- 一官多朝同名（如「太守」）：官职条目不含朝代，朝代进 `attested_in` 或匹配时由上下文决定。

### 3. 地名
- 古今地名同名异地、同地异名极多，**最难**。先做「地名词条＋沿革」而非坐标：
  - 数据源候选：CBDB `ADDR_CODES`（附行政区划层级）、CHGIS（哈佛历史 GIS，有时间序列）、中国历史地名数据库。
  - 条目字段：`primary_name`、`alt_names`、`admin_level`（路府州县）、`dynasty`、`parent`、`modern_equivalent`（今地）、可选经纬度、外部 id。
  - 一个古地名在不同朝代可属不同行政级别 → 以「地名条目＋时段沿革数组」建模，不拆成多条。
- 文本里的地名先按**字面**建 candidate，不强行消歧；歧义的保留多个候选，由人裁。

### 4. 年号（新增类别，entity type 暂名 `reign`）
- 年号是断代的主要依据（「萬歴」「乾隆」「景祐」「元祐」），文本里极常见，且是人物生卒、事件、版本年代的锚点，价值高于普通地名。
- 数据：闭集，约 1,000+ 个（含改元、少数民族政权、农民政权年号）。来源候选：CBDB 的 `NIAN_HAO` 码表（运行时读库）、《中国历史纪年表》类公开数据；以人工可审的表为准。
- 条目字段：`primary_name`、`alt_names`（异体、避讳改字，如 萬歴／萬曆）、`ruler`（指向人物条目：帝号／庙号）、`dynasty`（指向朝代条目）、`start_year`、`end_year`（公元年，另存干支）、`index_in_reign`（该帝第几个年号）。
- 重名处理：同名年号多见（如「建元」「太平」「永安」），必须靠朝代＋上下文消歧；`ambiguous` 候选保留，不强配。
- 文本侧 type：entity.json 新增 `reign`（目前徽宗、孝宗、萬歴 这类被误标 `dynasty`，P0 清洗时分流：庙号／帝号→people，年号→reign）。
- 年号后的纪年串（「萬歴三十年」）：只标年号本体，年数不入 span；纪年换算（→公元）作为读者端派生功能，另议。
- 价值联动：年号条目挂上朝代与帝王后，人物 `dynasty` 补全、版本著录里的「乾隆刻本」可直接反查。

## 五、回挂（匹配）策略

- 匹配键：规范化后的字面（异体字归一，复用现有 variant 表）＋类型＋朝代上下文。
- `target.status`：`matched`（唯一命中）／`new_candidate`（无命中）／`ambiguous`（多命中，新增，保留 `candidates` 数组）。
- 回挂只改 entity.json 的 target，**不动 char／punct**；按 minor 升 entity 线，写 CHANGES.md。
- 每次入库后批量重跑回挂，已 matched 的不回退（与书名匹配策略一致：目录扩充后再配）。

## 六、质量保证

- P0 清洗和每次回挂后：`anchor_mismatches(char,'entity',data)` 必须为 0；
  抽样人工核对每类 ≥50 条，错配率 >2% 回退规则。
- 朝代、官职、地名四类各留一份「误标黑名单」（如 帝号、人名），防止下次抽取又进来。
- CBDB 的编码（朝代、官职码）一律运行时读库，不抄进代码（沿用 CBDB 方案 §教训）。

## 七、需要用户／目录总管定的事

1. `office`、`place`、`dynasty`、`reign`（年号）四个 subtype 是否按本文方案立（SCHEMA.md 现为预留，规划/目录.md 说 schema 变更等朋友的新设计）；
2. 年号作独立 `reign` 类（本文推荐），还是并入朝代子项；年号与朝代／帝王的引用关系是否按本文字段；
3. 复合官名的 `base_office`／`qualifier` 拆分字段是否接受；
4. 地名条目是否带坐标，还是第一期只做沿革与今地对照。

## 八、不做

- 不在文本仓里自建四类条目（条目归目录）；文本侧只出 candidate 清单与回挂。
- 不为消歧而改原文；歧义保留。
