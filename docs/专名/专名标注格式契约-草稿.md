> T 小总管起草，2026-10-08（洛杉矶）。对应 #478 §五。**草稿**：网站经理（#464）确认前不批量写；改契约走 `cross` 卡。

## 一、记法（沿用现有 entity.json，不新造）

每个 span 一条：`id`、`type`、`text`、`anchor{start,end}`、`span{start_offset,end_offset}`、`target`、`source`。
`type` 取值：`work`／`people`／`place`／`office`／`dynasty`／`reign`（`reign` 待网站确认，见 #464）。

## 二、`target`

| `status` | 必带字段 | 说明 |
|---|---|---|
| `matched` | `entity_id`、`canonical_name`、`href`（`book-index://<Type>/<id>`） | 键表唯一候选且无 `ambiguous` |
| `ambiguous` | `candidates[]` | 多候选或键表带 `ambiguous` |
| `new_candidate` | `canonical_name` | 查不到；回 #464 由目录补条 |
| `external` | 外部引用 | 保留 |

可选：`level`（`concept`／`concrete`，官职定不了朝代时挂概念条）、`note`、`coarse`、`reclass`、`route_to`。

## 三、复合官名（待目录与文本经理定稿）

`decomposition`：`{"mode":"split|tail_only","institution":<span 内片段>,"base":<片段>,"scope_text":<可选>}`。
整串命中 C 类固定复合键时不拆（O 设计档 §四·4.2）。拆出的片段各自匹配，不重复入 `entities`。

## 三·二、复合地名（decomposition，N 裁定 10-07，P-地名-设计 §十三；待网站认可后生效）

一个 span 带 `decomposition`，不重切 span（与 A 类复合官名同理）：

```json
{
  "id": "e00123", "type": "place", "text": "泰州如臯",
  "anchor": {...}, "span": {...},
  "target": {"status": "new_candidate", "canonical_name": "泰州如臯"},
  "decomposition": {
    "mode": "split",
    "parts": [
      {"text": "泰州", "level": "州", "offset": [0, 2], "target": {"status": "new_candidate", "canonical_name": "泰州"}},
      {"text": "如臯", "level": "縣", "offset": [2, 4], "target": {"status": "new_candidate", "canonical_name": "如臯縣"}}
    ]
  }
}
```

- `mode` 取值同官名（`split`）；`parts` 按文本顺序，依次为上级、下级；每个 part 的 `target` 与普通 span 的 `target` 同形（`matched` 才带 `entity_id`／`href`），`offset` 为 part 在 span 内的字序偏移，`level` 只作提示。
- 顶层 `target` 保留整串的状态（整串不是一个行政区时记 `new_candidate`，不拿它做链接）；渲染按 parts 各画线、各链接。
- 范围：只拆「州＋縣」这类行政区划复合（泰州如臯、潭州寧鄉、台州臨海、南康都昌）；山水名（雲谷、武夷山、石門山、龜山）、区域泛称（江南、閩）、别称（温陵、東都）、域外政权（新羅、蜀）第一期不建条，保留 `new_candidate`，不配、不强取前缀。
- 籍贯「X人」：span 边界不含「人」（临川人 → span=臨川）；改边界属文本侧清洗，另行出清单。
- 生效前不写任何 id、不改现有 `target`。
