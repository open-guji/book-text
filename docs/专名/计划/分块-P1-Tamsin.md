## 一、本块目标与边界
目标：在册 002／003 整理本里，找出「库里有名、文中有字、未被任何实体盖住」的人名（N8）与书名（N9）位置，出候选表　｜　不做：不补标（归 P2）、不改正文与标点、不建档　｜　交付物：脚本 `scripts/book-text/entity_missing.py`＋`专名匹配/漏标候选-册002.tsv`／`-册003.tsv`＋`专名匹配/漏标处置.tsv`（空表头，P2 填）

## 二、Schema／数据格式（完整）
**候选表** `专名匹配/漏标候选-册<NNN>.tsv`（UTF-8，制表符，首行表头）

| 字段 | 类型 | 可空 | 含义 |
|---|---|---|---|
| cand_id | str | 否 | `M<册>-<序号4位>`，如 `M002-0017` |
| vol | str | 否 | `002`／`003` |
| kind | enum | 否 | `N8_person`／`N9_work` |
| text | str | 否 | 命中的原文字串 |
| len | int | 否 | 字数 |
| anchor | str | 否 | 与 `*.entity.json` 同格式 `行:段:字`（`start`） |
| offset | int | 否 | 该册 `*.char` 文本内起始偏移（与 entity `span.start_offset` 同口径） |
| ctx | str | 否 | 前后各 10 字上下文，命中处用 `【】` 括起 |
| match_id | str | 否 | book-index 里唯一命中的 Entity／Work id；多命中填 `ambig:<id1>|<id2>` |
| guide | str | 是 | N9 的引导词（撰／著／作／載／云／見）；N8 留空 |
| risk | enum | 否 | `hi`（三字以上、非停用词）／`lo`（两字名、停用词近邻、数字邻）|

**处置表** `专名匹配/漏标处置.tsv`：`cand_id`｜`decision`（`补标`／`不标`）｜`reason_code`（`ok`、`数字`、`年号`、`普通词`、`氏`、`已被长实体覆盖`、`同名异人`）｜`target_id`（补标时必填）｜`by`｜`date`。

样例行（候选表）：`M002-0017	002	N8_person	朱震	2	4:5:10a	1203	…作《漢上易傳》者【朱震】…	e03941		lo`

与共用契约：补标后的新实体按总计划 §五「entity 记录格式」落入 `*.entity.json`，由 P2 写入，P1 不写。

## 三、程序架构
- 新写 `scripts/book-text/entity_missing.py`（~150 行，只读）：读 book-index 名索引（`name→[id]`，含别名；索引来源 `book-index/index/`，路径作参数）＋ 册 `*.char`／`*.entity.json`；对每个名滑窗匹配，扣除已被实体 span 覆盖的位置；输出 TSV。
- 复用：`项目进展/古籍文本/scripts/zi_convert.py` 异体归一（N4，仅查键时用）；`entity_coverage.py` 的读取逻辑。
- 配置：停用词表 `专名匹配/漏标停用词.txt`（開元／易之／數字串…，一行一词，随 P1 迭代追加）。
- 入口：`python3 entity_missing.py <book-text> <book-index> [--vol 002] [--out DIR]`；`--check` 读处置表，每个 cand_id 必须有处置，否则退出码 1 并列出缺的 id。
- 运行在云端会话，只读，耗时 <5 分钟。
