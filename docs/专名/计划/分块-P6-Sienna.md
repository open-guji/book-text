## 二、Schema／数据格式（完整）
**不新增、不改字段**，沿用 `schema/entity.md`〈五·二〉〈五·三〉〈六〉。本块用到的字段：

| 子类型 | 必填字段（摘） | 校验码 |
|---|---|---|
| place | `primary_name`；`history[]`（非空，每项 `name`、`level` 必填，`start/end/dynasty_ids/parent_id/note` 可选）；`modern{text,relation}` 可选 | P01–P04、P06、P08、P10、P11 |

| dynasty／reign | 已升格（139／734），本块只可能补 `alt_names` | D1–D3、R1、A1 |

**本块新增的是三份账（markdown 表，非数据字段）**：
- 建档结果表 `建档结果-地官朝号.md`：列 `#｜规范名｜类型｜草稿 id｜正式 id｜来源（升格／新建）｜说明`。样例：`1｜婺源縣｜place｜1jb8ku5oqg1gn｜<升格后新铸>｜升格｜命中 4`。
- 不建档清单：列 `条目｜册｜锚点｜类型｜理由码｜说明`，理由码沿用 `类型清洗清单` 的分类：`山水名`、`区域泛称`、`别称待消歧`、`域外政权`、`复合须拆`、`人名误标`。样例：`石門山｜003｜e00335｜place｜山水名｜不得取前缀「石門」`。
- 逐条处置表 `处置-地官朝号.tsv`（工作表，步 2 起）：`type｜text｜册:id｜现状(new_candidate/ambiguous/matched)｜处置(升格/新建/改别名/不建档/转A)｜目标 id｜依据`。

升格的 id 规则：草稿 id→正式 id 的唯一权威是正式库 `promotions/` 分片（`schema/promotions.md`），**只经 bim `bim promote` 写，不手改**；正式库条不得指草稿 id（`schema/entity.md` 〈六·一〉）。
