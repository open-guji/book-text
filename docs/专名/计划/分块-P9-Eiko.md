## 一、本块目标与边界
目标：线上随机抽 30 个已链接专名，逐个点开，证明每个专名号都能到达对应条目页（或弹出正确卡片），证据可复核　｜　不做：不改渲染代码（专名线 #134 归 Ella）、不改数据（`href` 失效归 Tilda／P7）、不做全站爬取、不替代 P7 的对现库重对　｜　交付物：`kaiyuanguji-web/e2e/tests/entity-links.spec.ts`＋`e2e/entity-links/`（样本清单与 README）、`项目进展/专名识别与链接/线上验收/<日期>-P9结果.md`（结果表＋证据位置）

**前置条件（须写清，线上验收暂不能跑）**：
1. P5 批 2 建档、P6 地官朝号建档、P7 回挂两轮，三者的线上 data 发布都已完成（网站 Mason 按滚动发布规矩晋升）。Tilda 在 #574 报 book-text／book-index 的完整 SHA，晋升后 P9 才开始。
2. 第一轮只能在 P5／P6 上线后做；第二轮在 P7 第 2 轮上线后补跑，才算收口验收。
3. 在这之前可做「预演」：对 staging 跑同一脚本，结果只作脚本自检，不计入验收，结果文件名标 `预演`。
4. 样本清单（第二节）在脚本写好后、P5／P6 上线前就能生成（取自 vol02／03 现状实体，与发布无关）；验收的 30 个专名以样本清单为准，不临时换。

## 二、抽样规则与样本清单
**总体**：vol02／vol03 的实体线中 `target.status = matched` 且带 `href` 的专名（P1–P3 之后的口径；现状约 46% 链接率，即 1,000 上下的可点专名，以生成日实测为准）。

**分层配额（共 30）**：
| 类型 | 配额 | 说明 |
|---|---|---|
| person（人名） | 12 | 人物条目页 |
| work（书名） | 10 | 书目条目页 |
| place／office／dynasty／reign（地名、官署、朝代、年号） | 8 | 统一按 P6 口径分层，每类至少 1 个；某类总体为 0 时，配额并给 person |

**抽样方法**：
- 种子固定为 `20261012`，PRNG 用 Python `random.Random(seed)`（或脚本内同等的 mulberry32，需写进代码常量）。
- 总体先按 `(册, 章, 锚点 offset)` 字典序排序，再在每层内用 `sample(k)` 抽。排序保证与文件顺序无关，换机器结果一致。
- 同一 `canonical_name` 最多抽 1 个，避免同一条目验了两次。
- 输出 `e2e/entity-links/sample-vol02-03.tsv`：列 `id｜类型｜册｜章｜text｜canonical_name｜href｜seed`。该文件入仓，**不临时换**；若需换，只能在 #574 说明后另立一版文件名（如 `sample-…-v2.tsv`）。

## 三、点击验证判据
每个专名跑完 4 项，**全部通过**才算该专名通过；30 个全过才算 P9 通过。

| 项 | 判据 | 失败归属 |
|---|---|---|
| ① 可点 | 页面上存在对应专名号元素（`href` 或带专名号的 `data-*` 节点），可见、可点击，点击后未报错 | 渲染→Ella（#134） |
| ② 落点正确 | 点击后出现卡片（卡片标题＝`canonical_name`），**或**跳转到的 URL 与样本 `href` 指向同一条目（允许升格跳转：跳转链中最终 URL 对应的条目 ID 与样本 `href` 的条目 ID 一致，且跳转链写入记录） | 数据（`href`、升格）→Tilda／P7；渲染→Ella |
| ③ 页面有效 | 落点页 HTTP 200，页面非空，标题与 `canonical_name` 对得上（允许繁简差异，比较时统一转繁） | 数据→Tilda；HTTP 错误→网站（Mason） |
| ④ 升格跳转记录 | 若发生跳转，记录 `from → to`，并核对 `promotions.json` 中有该条；若无对应记录但发生跳转，判失败 | 数据→P7 |

**证据**：每个专名记一行结果（`结果.tsv`：`id｜类型｜text｜点击前 URL｜最终 URL｜HTTP｜标题｜跳转链｜①②③④｜截图文件名`）；截图每个专名一张 PNG，只留点击后的落点状态。

## 四、脚本与运行环境
- 框架：复用 `kaiyuanguji-web/e2e/` 现有的 **`@playwright/test`（1.58）**，新增一个 project `entity-links`，与 `contract`／`ui` 并列；用**真 Chromium**（配置里 `executablePath: '/opt/pw-browsers/chromium'`，不跑 `playwright install`，不跑 jsdom 之类的模拟）。
- 位置：`kaiyuanguji-web/e2e/tests/entity-links.spec.ts`（测试）、`e2e/entity-links/sample-vol02-03.tsv`（样本，入仓）、`e2e/entity-links/README.md`（用法与页型选择器表）。
- 运行：`npm --prefix e2e run test -- --project=entity-links`；base URL 走环境变量 `ENTITY_LINKS_BASE`（默认正式站，预演时指向 staging）；产物输出到 `e2e/out/`（已忽略）。
- 退出码：任一专名不过 → 非零退出（Playwright 原生行为），失败清单由 spec 的 `afterAll` 写进 `结果.tsv`。
- 逐个串行跑（`workers: 1`，不并发，降低对线上的压力），每两个专名之间间隔 ≥1 秒，遇 429 退避并记录。
- 本 project 不挂进 `test.yml` 的 PR 流程（它打线上，PR 不该碰线上）；只手动触发。

- **运行元数据**：结果表首行写明 base URL、book-text／book-index 完整 SHA、样本文件 SHA、脚本 commit、Chromium 版本、运行时间（洛杉矶时间）。

## 六、失败怎么回报
1. 脚本本身报错（样本读不了、浏览器起不来）→ 当次不计结果，在 #574 写原因，不改判准。
2. 专名判失败 → 失败清单按归属分组（渲染→Ella，数据→Tilda／P7，网站→Mason），每条写 `id`、失败项、落点 URL、截图名。
3. 失败 ≥1 时 P9 不通过；修复后**重跑全部 30 个**，不只重跑失败的（避免挑着跑）。
4. 修复若在 P7 数据上，需要重新发布再验；不改样本、不剔除失败项。

## 九、风险与未决
- **最可能出错的一处**：站点的专名号在不同页型下渲染不一致（人物页、书目页、阅读页），脚本的选择器若只覆盖一种页型，会假阴性。对策：步 2 预演先按页型各截一张，写进 README；选择器失败记为「定位失败」，归渲染，不算数据问题。
- 升格跳转后 `href` 本身仍指旧 ID，判准②靠跳转链与 `promotions.json` 对；若 `promotions.json` 线上未随发布更新，会误判。对策：④项强制核对，不通过即记数据问题。
- 线上对脚本有访问压力：串行＋间隔，已写第四节。
- 未决：Mason 是否同意「预演用 staging」的做法（默认同意，若不同意则只在前置条件满足后才跑）。
