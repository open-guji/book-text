## 一、目标（一句话＋为什么）
让四庫總目（先 vol02／03，再 vol04 起逐册）的专名号**全部有处置**：每个专名要么链到 book-index 的 Entity／Work，要么明确登记「不建档」及理由；线上读者点专名号能打开对应条目。

为什么：vol02／03 实体层现在只有 46.0% 链得上，727 个书名、155 个人名还是「候选」，152 个同名待消歧；后面 vol04–vol10 要按同一套判准批量做，判准与建档能力不先落稳，后面每册都会重复返工。

## 二、不做什么（先写）
- **不动正文与标点。** 标点线归 #535（`punct` 线），本项目只改 `entity` 线，两线各自升版本（`bump_original.py`）。
- **不做 vol04 起各册的整理本本身**（char／punct 的生成）——归「四庫整册整理」项目（#10，Lucian）；本项目只管它们的实体层接入与验收，且只试 vol04 一册。vol05–vol10 的实体层按本项目沉淀的脚本与判准，作为常规批次，**不在本项目内全做**。
- **不做 person 全库对齐 CBDB（#395）与人物去重尾巴（#483）**：前者另有项目线、后者用户定低优先排队。本项目建档时附带的 CBDB 号照写（批 1 做法），不额外扩范围。
- **不改网站渲染代码**（专名号怎么画、怎么点）：归网站（Mason）。本项目只出数据与验收清单。
- **不改 schema**：S0 冻结（Schema落地），实体 JSON 与 Entity 记录沿用现行格式。
- 书影核对（`F-MD-11` 疑字等）不归本项目，需要时走 Mila（CV）。

## 五、总体架构与共用契约
```
整理本 vol02/03 (char/punct 真源)
      │  P1 漏标候选 ──→ P2 补标/判读 ──→ entity.json (候选/ambiguous/matched)
      │                                      │
      │                  P3 消歧 ────────────┤
      │                                      ▼
      │               P4 建档清单 ──→ P5/P6 建档(book-index PR, check_schema 绿)
      │                                      │ 线上 data.yml 发布(网站总管)
      ▼                                      ▼
vol04.. Gemini 输出 ──→ P8 entity_postprocess ──→ P7 回挂(对现库重对, span 回挂) ──→ P9 线上验收
```
| 接口 | 谁产出 | 谁消费 | 格式在哪里 |
|---|---|---|---|
| entity 记录格式 `{status, entity_id, canonical_name, href: book-index://Work/<id>, note?}`＋`stats` | book-text | 网站 `TextReader`、`index/texts` | guji-format `spec/05`（C4）；`stats` 由 `bump_original.py` 流程重算 |
| 建档清单（人名／书名／别名／CBDB 号／不收理由） | P4（Tamsin） | P5（Soren） | 同批 1 的 `建档清单-批1.md` 版式 |

| 草稿 id 升格跳转 | book-index `promotions.json` | P7 回挂脚本 | Schema落地 C1／C3 |
| 不建档登记 `不建档清单.md` | P4 | P7（不重复报）、P9（不当作未链接） | 本项目 P4 设计中定列：条目、册、锚点、类型、理由码 |

**共用同一窗口／配置／文件的其他线**
- **`96mid1ogzk/default` 下的 `entity.json`、`index.json`（`entity_version`）、`CHANGES.md`**：同时被 #535（标点线）、Schema落地 B3（步 2(a) 只动 `CHANGES.md`）、#564（vol04 起）触碰。规则：**同一时刻只允许一个 PR 在改 entity／punct 线版本**；PR 排队顺序由 Maren 定，后合的先把 main 合进分支、再重建 `index/texts`。已知 `CHANGES.md`、`index.json` 冲突按 B3 的做法（保留两边行，取最新版本号）。
- **book-index 写入**：P5／P6 两个 PR 不得同时改同一 Work／Entity 文件；P5 管人物（Entity）与书名（Work），P6 管地名／官署／朝代／年号，写域天然不相交。
- **`bump_original.py --pr` 现为必填**（B3 步 2(a)，overview `835e16d2`）：所有 entity 版本升级先开 PR 再升版本。

## 六、项目验收标准（几条可验的话）
1. **vol02／03 无悬案**：`python3 scripts/book-text/entity_coverage.py <book-text>` 的「全部／合计」行 `ambig` 为 0，或剩余条目全部逐条登记在 `专名匹配/仍待消歧.md`（带候选 id 与理由）。
2. **漏标有处置**：`python3 scripts/book-text/entity_missing.py <book-text> --check` 退出码 0（候选表每行在处置表里有「补标／不标＋理由」，未处置 0）。
3. **候选有去向**：`new_candidate` 的每个 span 要么已变成 `matched`，要么在 `不建档清单.md` 有一行（理由码）。验证：`entity_coverage.py` 的 `new` 总数＝`不建档清单.md` 行数（脚本比对，差值 0）。
4. **链接率参考线（估，待 Maren 定）**：people ≥ 90%、place／office／dynasty／reign ≥ 95%、work ≥ 60%（大量佚书不建档，按「不建档」排除后分母另算）。
5. **版本与校验**：book-text main 上三项校验通过（`validate_text_format --strict --baseline`、`validate-collated`、重建 `index/texts` 无 diff），CI 运行 ID 贴出；`entity` 线版本每次升级有 `CHANGES.md` 行且 PR 栏非空。
6. **线上可点**：P9 抽样 30 个专名点开，30 个都到达对应条目页（贴 URL 清单与结果）。
7. **vol04 试跑**：vol04 第 1 份 Gemini 输出与 Claude 对照 F1 ≥ 0.9（#564 口径），`entity_postprocess.py` 跑完后人工抽 30 个 span，假命中 ≤ 2；达不到则写原因并**停在 vol04**，不向 vol05 推。
8. **旧物清理**：`scripts/book-text/` 下 `t543_*.py` 临时脚本归档到 `scripts/book-text/archive/` 或并入通用脚本，README 一页说明；没有遗留「在跑」标签的 issue（#543、#489、#435、#401、#397 关闭或写明转去哪张卡）。
9. **M2 验收（路线图 #618，用户令 10-13）**：四庫 1–3 册「标点准确、专名号可点且链到 entity」。标点按**宽口径候选错误率**验收（口径见 `四庫标点与专名自动化/计划/分块-M4-1-标点规则抽取.md` §三，不写「对金标 F1」），样本只从 dev 段抽、不与留出集重叠（Maren 10-13 定，GUJI-150）；前置：GUJI-173（引号 9 处未闭合、002 的 74 个《》无 work 实体）清零。专名号可点＝验收 6，链到 entity 先用 B 侧现有实体（GUJI-153）。
